# Вики сеттинга — инструмент ворлдбилдинга для НРИ

**Сайт:** https://solarvonbro.github.io/dezremon-wiki/ · Firebase-проект `dezremon-wiki-6118` (Spark, Firestore eur3)

Вики для настольной ролевой игры по образцу [Kanka](https://kanka.io): статьи о персонажах, локациях, фракциях,
предметах и событиях, связанные между собой; карты с метками, календари, хронологии, родословные, граф связей.
Мастер пишет и прячет секреты, игроки читают то, что им открыто, гости видят публичную часть мира.

## Возможности

- **Редактор**:
  - любое форматирование: стили абзацев, шрифты, размер, цвет, выделение, выравнивание, интервалы, отступы;
  - таблицы: объединение ячеек, заливка, ширина колонок, заголовки;
  - изображения в любом месте (в тексте, в таблицах, со смещением влево или вправо): вставка из буфера,
    перетаскивание, изменение размера мышью, подписи;
  - режим HTML-кода с подсветкой синтаксиса;
  - врезки, колонки, спойлеры, видео, HTML-блоки;
  - `@`-ссылки на статьи (можно сразу создать новую), меню команд по `/`, поиск и замена;
  - автосохранение без перезагрузки, черновик на случай сбоя, история версий;
  - секретные блоки мастера.
- **19 типов статей**, как в Kanka, плюс свои типы. Для каждой статьи есть:
  - поля типа и иерархия (город → регион → королевство);
  - теги, атрибуты (в том числе приватные) и шаблоны атрибутов;
  - разделы-посты со своей видимостью;
  - инвентарь, способности с зарядами, внешние ссылки;
  - даты в календарях, обратные ссылки, шаблоны статей, корзина.
- **Связи**: отношения между статьями, граф связей мира, родословные (родители, супруги), участники организаций,
  элементы квестов.
- **Модули**:
  - интерактивные карты на Leaflet: слои, группы, метки, круги, многоугольники;
  - фэнтези-календари: свои месяцы, недели, луны, сезоны, високосные годы, повторяющиеся события;
  - хронологии с эпохами;
  - разговоры и броски кубов.
- **Доступ**: владелец, мастера, игроки по ссылке-приглашению, гости в открытом мире. Видимость задаётся у каждой
  статьи, раздела, связи, метки и картинки: всем, участникам, выбранным игрокам или только мастеру. Права
  проверяются правилами Firestore на сервере.
- **Данные**: поиск по названиям и по всем текстам, галерея, закладки и избранное, тёмная, светлая и «пергаментная»
  темы.
- **Бэкап**: полная выгрузка мира в ZIP (данные, картинки, читаемая офлайн-копия HTML) и восстановление из неё;
  ежесуточный автобэкап в приватный репозиторий; импорт из экспорта Kanka.

## Стек

- **Сайт**: Vue 3, TypeScript, Vite, Pinia, vue-router, TipTap 3, CodeMirror 6, Leaflet, d3-force, MiniSearch.
- **Хостинг**: GitHub Pages, сборка и деплой через GitHub Actions (`.github/workflows/pages.yml`).
- **База и вход**: Google Cloud / Firebase — Cloud Firestore и Firebase Authentication (Google или почта и пароль),
  бесплатный тариф Spark.

Схема данных и права описаны в [docs/SCHEMA.md](docs/SCHEMA.md), соглашения для разработки — в
[docs/DEV_NOTES.md](docs/DEV_NOTES.md).

## Локальный запуск

```bash
npm install
npm run dev                # http://localhost:5173, работает с настоящим Firebase-проектом
```

С эмуляторами Firebase (нужна Java 21+):

```bash
npm run emulators          # Firestore :8080 + Auth :9099
npm run dev:emu            # сайт подключится к эмуляторам
```

## Проверки

```bash
npm run typecheck                 # типы
npm run test:rules                # 41 тест правил Firestore (нужен запущенный эмулятор)
pip install playwright            # браузерные сценарии (системный Chrome)
python tests/e2e_smoke.py shots   # регистрация, статья с таблицей/картинкой/секретом, игрок по приглашению
python tests/e2e_modules.py shots # календарь, карта, хронология, родословная, граф, поиск, бэкап
```

## Деплой

- **Сайт**: любой push в `main` собирает его и публикует на GitHub Pages.
- **Правила и индексы Firestore**: `npm run deploy:rules` (нужен `firebase login`).
- **Firebase web-конфиг**: лежит в `src/firebaseConfig.ts`. Он публичный по задумке — доступ ограничивают правила.

## Лимиты бесплатного тарифа

| Ресурс | Лимит |
|---|---|
| Хранилище | 1 ГБ (вместе с картинками — они сжимаются до WebP) |
| Чтения | 50 000 в сутки |
| Записи | 20 000 в сутки |

Сайт кэширует данные в браузере и подтягивает только изменения, поэтому обычной группе этого хватает с запасом.
Большой импорт из Kanka может занять больше одного дня по записям.
