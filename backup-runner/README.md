# Автоматический бэкап Dezremon Wiki (GitHub Actions)

Скрипт раз в сутки выгружает **все миры** из Firestore в отдельный приватный git-репозиторий:

```
backups/
  <worldId>/
    manifest.json          описание копии (тот же формат, что у кнопки «Скачать ZIP» в приложении)
    world.json             документ worlds/<worldId> (название, настройки, пользовательские типы)
    data/<коллекция>.json  все документы: entities, bodies, secrets, posts, relations, …, members, invites
    data/users.json        профили участников мира (users/<uid>)
    images/<id>.<ext>      изображения, собранные из imageChunks
```

Файлы перезаписываются, только если изменилось содержимое, а изображения (они неизменяемы) скачиваются один раз,
поэтому ежедневные коммиты маленькие, а история git хранит все прошлые версии мира. Если за сутки ничего не
поменялось, коммита не будет.

## Настройка (один раз, ~10 минут)

1. **Создайте приватный репозиторий** на GitHub, например `dezremon-backups`. Только приватный: в копиях есть
   секреты мастера и почты участников.
2. **Скопируйте в него** эту папку целиком (`backup-runner/`), а файл `backup-runner/workflow.yml` — в
   `.github/workflows/backup.yml`:
   ```
   dezremon-backups/
     .github/workflows/backup.yml
     backup-runner/package.json
     backup-runner/backup.mjs
     backup-runner/zip-backup.mjs
   ```
3. **Создайте ключ сервисного аккаунта**: Firebase Console → ⚙ Настройки проекта → *Сервисные аккаунты* →
   *Создать закрытый ключ* (Generate new private key). Скачается JSON-файл.
4. **Добавьте секрет**: в репозитории *Settings → Secrets and variables → Actions → New repository secret*,
   имя `FIREBASE_SA`, значение — **всё содержимое** JSON-файла (можно и в base64). Сам файл потом удалите с диска.
5. **Проверьте**: вкладка *Actions → Firestore backup → Run workflow*. Через минуту-две в репозитории появится
   папка `backups/`. Дальше бэкап запускается сам каждый день в 02:23 UTC (время меняется в `cron`).

Необязательно: выполните `npm install` в `backup-runner/` локально и закоммитьте `package-lock.json` — тогда
workflow будет ставить зависимости через `npm ci` с точными версиями.

## Расход лимитов

- **Firestore (тариф Spark: 50 000 чтений в сутки)**: один запуск читает каждый документ всех миров один раз
  (+ части изображений, но только новых). Мир на 2 000 статей — это примерно 5–8 тысяч чтений. Если миров много
  и они большие, запускайте реже (например, `cron: '23 2 * * 1,4'`) или выгружайте один мир (`--world`).
- **GitHub**: приватному репозиторию бесплатно доступно 2 000 минут Actions в месяц, запуск занимает 1–3 минуты.
  Размер репозитория лучше держать до нескольких гигабайт — изображения в Firestore и так не больше 3,5 МБ.

## Восстановление

1. Склонируйте репозиторий (или скачайте его ZIP с GitHub) и выберите нужную версию через историю git, если
   нужна не последняя (`git checkout <commit> -- backups/<worldId>`).
2. Упакуйте папку мира в архив:
   ```
   node backup-runner/zip-backup.mjs backups/<worldId>
   ```
   Получится `<worldId>-<дата>.zip` с `manifest.json` в корне.
3. В приложении: *мир → Резервные копии → Восстановление*, выберите архив и режим «в новый мир» или
   «заменить текущий мир».

Подойдёт и обычный ZIP папки мира, сделанный архиватором: приложение найдёт `manifest.json` во вложенной папке.

## Запуск вручную на своём компьютере

```
cd backup-runner
npm install
FIREBASE_SA="$(cat ~/Downloads/ключ.json)" node backup.mjs --out ../backups            # все миры
FIREBASE_SA="$(cat ~/Downloads/ключ.json)" node backup.mjs --out ../backups --world ID # один мир
```

В PowerShell: `$env:FIREBASE_SA = Get-Content ключ.json -Raw; node backup.mjs --out ..\backups`.

## Безопасность

- Ключ сервисного аккаунта даёт **полный доступ** ко всему проекту Firebase в обход правил безопасности. Храните его
  только в секретах GitHub, никогда не коммитьте. Если ключ утёк — удалите его в Google Cloud Console (IAM →
  Сервисные аккаунты → Ключи) и создайте новый.
- Скрипт только **читает** Firestore, ничего не изменяет.
- Миры, удалённые из Firestore, из бэкапа автоматически не удаляются.

## Формат

Формат совпадает с ZIP из приложения (`src/data/backup/format.ts`): JSON-файлы с отсортированными ключами,
специальные значения Firestore записаны как `{"__fs":"timestamp"|"bytes"|"geopoint"|"ref", …}`. Отличия от
браузерного архива: нет офлайн-копии `html/` (`"html": false`), есть `data/users.json` (при восстановлении
игнорируется), `"generator": "backup-runner"`. Если формат в приложении меняется, обновите и `backup.mjs`.
